## Controlled prompt setup

Sixteen case descriptions and protected business/technical boundaries are in `D2_BEHAVIORAL_CASES.json`. The same request text, source snapshot metadata, relevant Golden content and output format are supplied to both policy variants. Only the policy payload differs: full v26.8 Master + Index + Registry versus v27 core + relevant modules or verified full fallback + Registry. The reference decision and required gates are **not** included in the model prompts.

## Integrity and negative tests

The scorer rejects absent model outputs, synthetic response labels, incomplete paired evidence, model/effort mismatch, stale prompt hashes, unsafe decision classes, missing required gates and absent independent qualitative review. A further check binds declared decision and gates to the actual parsed JSON response body, so external metadata cannot silently claim a different PASS result. This is a **protocol validation**, not proof that any real model made a correct decision.

## Blockers before v27E

- Run each of the 16 prompts under both policy variants using a real model, same explicitly recorded model and reasoning effort, separate request IDs, prompt hashes and trustworthy input/output usage/timing receipts.
- Independently evaluate every resulting rationale and proposed action against expected product/security/release policies, with zero severe regressions.
- Record comparable end-to-end development measurements (actual first edit, exact-head CI and completed merge), without treating local resolver milliseconds as user-facing development time.
- On any behavioral regression, fix the v27 candidate and regenerate the full fallback in the same PR, then re-test; no waiver due to token savings.

The official `CURRENT.yaml` still resolves **Master v26.8**. No Anna, Phone Guard or AppLab repository was modified.
