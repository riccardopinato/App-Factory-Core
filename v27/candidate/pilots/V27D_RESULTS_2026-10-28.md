### Regression findings caught and corrected

1. **Missing parallel-first authority** on the Anna roadmap: the resolver originally selected UI/audit modules but not the complete `authority-execution` contract. Continuation triggers now include that contract; bare `Procedi` without a known task still falls back.
2. **False AppLab routing**: the repository name by itself incorrectly matched the delivery module. The generic project-name trigger was removed; it now uses fallback.
3. **Missing specialist PIN Golden**: a Phone Guard PIN/Keystore task now selects `android_local_pin_verifier_keystore`. The result explicitly marks it `REVIEW_REQUIRED_NOT_CERTIFIED`, because the registry classifies it as Draft/Needs Review.
4. **Routing/fallback drift**: the generated full fallback now serializes the current task-route catalog. A route-map change without regeneration causes a failed check.

All fixes are on the Factory candidate branch, not in the app repositories. Factory structural validation, full fallback synchronization and **12 candidate resolver unit tests** passed on the same exact head.

### Activation decision: HOLD

What this run **does not** prove:
- a generative agent makes the same product/security/authorization decisions when using modular vs full instructions;
- real conversation tokens or time to first edit/merge improve;
- any app was built, physically tested, certified or released;
- provider-sensitive Draft Golden rules are certified or freshly verified.

Before v27E, perform independent positive/negative model-policy evaluations on representative tasks with actual app context, then comparable live workflow/time measurements. Require no loss of safety gates and a reviewable rollback to the full, synchronized v27 fallback. **CURRENT.yaml must continue resolving v26.8 until those gates pass.**
