======================================================================
1. SCOPO
======================================================================

Verificare un PIN locale senza memorizzare il PIN e senza confondere PIN
verification con encrypted secret storage.

Questo Golden è complementare, non sostitutivo, a
GOLDEN_SECURE_STORAGE_ANDROID_KEYSTORE_FLUTTER_v1.

======================================================================
2. STORED MATERIAL
======================================================================

Persistenza minima:
- random per-install salt;
- derived verifier only.

NON memorizzare:
- raw PIN;
- reversible PIN;
- plaintext PIN in logs/analytics/backup.

======================================================================
3. DERIVATION
======================================================================

Pattern pilot:
1. validate format;
2. PBKDF2WithHmacSHA256(pin, random salt, bounded iteration policy, 256-bit);
3. HMAC-SHA256 del derived value usando SecretKey non-exportable in
   AndroidKeyStore;
4. persist salt + final verifier;
5. zeroize temporary char/byte buffers when practical.

Phone Guard pilot uses 210,000 PBKDF2 iterations.

Iteration count is a versioned tuning parameter, not a universal eternal value.

======================================================================
4. VERIFY
======================================================================

Verification:
- reject invalid format before KDF;
- load salt/verifier;
- derive with same parameters;
- compare constant-time;
- fail closed on decode/Keystore errors.

MessageDigest.isEqual or equivalent constant-time comparison is required.

======================================================================
5. KEYSTORE KEY
======================================================================

Use a dedicated alias and non-exportable HMAC key.

Define behavior for:
- key missing;
- key invalidated;
- reinstall;
- backup/restore mismatch;
- device migration.

Do not silently regenerate a key and keep treating an old verifier as valid.

======================================================================
6. BACKUP RULE
======================================================================

Security verifier material and related Keystore assumptions require explicit
backup/data-extraction policy.

A restored salt/verifier without the matching Keystore key must fail closed and
require owner reconfiguration.

======================================================================
7. BIOMETRIC BOUNDARY
======================================================================

Biometric unlock is a separate authentication path.

Do not derive the PIN from biometric data.
Do not treat biometric availability as PIN material recovery.

======================================================================
8. RATE LIMIT / UX
======================================================================

This Golden does not by itself provide anti-bruteforce policy.

Apps needing stronger resistance should define:
- attempt throttling;
- cooldown;
- lockout UX;
- reset/recovery path;
- local-only privacy boundary.

Avoid destructive lockout without a recovery contract.

======================================================================
9. TEST MATRIX
======================================================================
