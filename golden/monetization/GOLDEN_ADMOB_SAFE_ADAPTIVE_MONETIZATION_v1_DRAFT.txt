HARDENING 06/10/2026
--------------------

HARDENING 14/10/2026 — REAL ANDROID DONOR / UMP PRODUCTION
-----------------------------------------------------------
1. UMP ha DUE superfici da validare:
   - integrazione SDK/runtime nell'app;
   - configurazione server-side in AdMob > Privacy e messaggi.
   Una build corretta NON prova che esista un messaggio europeo pubblicato.
2. Un errore tipo "Publisher misconfiguration: no form(s) configured" va distinto
   da un bug dell'app: può indicare che l'App ID è valido ma il messaggio UMP non
   è ancora configurato/pubblicato nel pannello AdMob.
3. Pubblicare/modificare il messaggio UMP è configurazione server-side:
   se l'app integra già UMP correttamente non richiede una nuova APK solo per
   aggiornare testo, targeting, lingue o stato di pubblicazione del messaggio.
4. Un messaggio europeo può essere associato anche a UNA sola app. La funzione
   "consent sync across multiple apps" è separata e non è prerequisito per UMP.
5. Android threading:
   - MobileAds.initialize() può/deve essere spostato su background secondo la
     documentazione Google corrente;
   - le operazioni ad che richiedono UI thread, in particolare il load/show dei
     full-screen ad, devono essere marshalled esplicitamente sul main thread;
   - non propagare automaticamente Dispatchers.IO fino a InterstitialAd.load().
6. Failure isolation:
   un errore banner o interstitial non deve disattivare globalmente l'intera
   monetizzazione della sessione. Ogni placement fallisce in modo isolato salvo
   un vero errore globale di configurazione/consenso.
7. Diagnostic lane:
   - sample Test Ad Unit ID ufficiali;
   - UMP debug geography forzata solo in build/flow diagnostico;
   - log di loaded/failed + response info;
   - nessun traffico production durante test manuale/automation.
8. Production lane:
   - App ID / Banner ID / Interstitial ID forniti da configurazione production;
   - preflight fail-closed su ID mancanti/malformati;
   - Store candidate deve rifiutare i sample Google test ID.
9. Privacy/revoca:
   - privacy policy URL reale e pubblica nel messaggio europeo;
   - voce privacy/revoca nell'app quando richiesta;
   - physical test di riapertura delle Privacy Options dopo una scelta.
10. Il runtime AdMob/UMP è provider-sensitive: CI/AppLab non sostituiscono il
    test fisico del consenso e dei placement realmente abilitati.


Regola obbligatoria per tutte le app App Factory che utilizzano Google AdMob.

Obiettivi:

- massimizzare fill rate e rendimento;
- evitare layout obsoleti a dimensione fissa;
- ridurre il rischio di clic accidentali;
- mantenere UX e navigazione separate dalla pubblicità;
- supportare automaticamente schermi e orientamenti differenti;
- centralizzare consenso, Premium/Remove Ads e telemetria;
- usare una reference implementation comune e riutilizzabile.

## 1. Banner — regola standard

Non utilizzare normalmente:

```text
320x50
468x60
AdSize.banner
dimensioni hardcoded
```

Il default App Factory è:

```text
Anchored Adaptive Banner
→ larghezza disponibile reale
→ altezza calcolata da Google
→ slot dedicato nel layout
```

Per contenuti scorrevoli:

```text
Inline Adaptive Banner
```

Gli Inline Adaptive devono essere inseriti nel flusso della pagina e non sovrapposti al contenuto.

---

## 2. Posizionamento

L'annuncio deve sempre avere uno spazio proprio nel layout.

Vietati:

- overlay sopra contenuti;
- sovrapposizione con pulsanti;
- banner sopra CTA;
- banner attaccati a controlli frequentemente premuti;
- spostamenti improvvisi della UI quando arriva l'annuncio;
- posizionamenti progettati per aumentare clic accidentali;
- pubblicità indistinguibili dai controlli dell'app.

Principio:

```text
APP CONTENT

[ ADVERTISING SLOT ]

APP NAVIGATION
```

Il banner non deve diventare parte della Bottom Navigation.

Quando possibile evitare:

```text
contenuto
banner
bottom navigation
```

se banner e navigazione risultano visivamente o fisicamente troppo vicini.

## AdMob IDs

Usare una sola configurazione centralizzata.

```dart
import 'package:flutter/foundation.dart';

class AdMobIds {
  AdMobIds._();

  static const androidTestBanner =
      'ca-app-pub-3940256099942544/9214589741';

  static const iosTestBanner =
      'ca-app-pub-3940256099942544/2435281174';

  static const androidProductionBanner =
      'REPLACE_WITH_ANDROID_AD_UNIT_ID';

  static const iosProductionBanner =
      'REPLACE_WITH_IOS_AD_UNIT_ID';

  /// Returns null on unsupported platforms/Web Preview.
  static String? banner({required bool production}) {
    if (kIsWeb) return null;

    return switch (defaultTargetPlatform) {
      TargetPlatform.android => production
          ? androidProductionBanner
          : androidTestBanner,
      TargetPlatform.iOS => production
          ? iosProductionBanner
          : iosTestBanner,
      _ => null,
    };
  }
}
```

Le build debug/test devono usare sempre Test Ads.

Gli ID reali devono essere forniti tramite configurazione production e mai usati nei test manuali.

## AdaptiveBannerSlot

Widget standard riutilizzabile.

```dart
import 'package:flutter/material.dart';
import 'package:google_mobile_ads/google_mobile_ads.dart';

class AdaptiveBannerSlot extends StatefulWidget {
  const AdaptiveBannerSlot({
    super.key,
    required this.adUnitId,
    required this.adsEnabled,
  });

  final String adUnitId;
  final bool adsEnabled;

  @override
  State<AdaptiveBannerSlot> createState() =>
      _AdaptiveBannerSlotState();
}

class _AdaptiveBannerSlotState
    extends State<AdaptiveBannerSlot> {
  BannerAd? _bannerAd;
  AdSize? _bannerSize;
  int? _lastWidth;

  @override
  void didChangeDependencies() {
    super.didChangeDependencies();

    if (!widget.adsEnabled) {
      _disposeBanner();
      return;
    }

    final width =
        MediaQuery.sizeOf(context).width.floor();

    if (width <= 0 || width == _lastWidth) {
      return;
    }

    _lastWidth = width;
    _loadBanner(width);
  }

  Future<void> _loadBanner(int width) async {
    await _bannerAd?.dispose();

    final size =
        await AdSize.getLargeAnchoredAdaptiveBannerAdSize(
      width,
    );

    if (!mounted || size == null) {
      return;
    }

    final banner = BannerAd(
      adUnitId: widget.adUnitId,
      size: size,
      request: const AdRequest(),
      listener: BannerAdListener(
        onAdLoaded: (ad) {
          if (!mounted) {
            ad.dispose();
            return;
          }

          setState(() {
            _bannerAd = ad as BannerAd;
            _bannerSize = size;
          });
        },
        onAdFailedToLoad: (ad, error) {
          debugPrint(
            'AdMob banner load failed: $error',
          );
          ad.dispose();

          if (mounted) {
            setState(() {
              _bannerAd = null;
              _bannerSize = null;
            });
          }
        },
        onAdImpression: (ad) {
          debugPrint('AdMob banner impression');
        },
        onAdClicked: (ad) {
          debugPrint('AdMob banner click');
        },
      ),
    );

    banner.load();
  }

  Future<void> _disposeBanner() async {
    await _bannerAd?.dispose();
    _bannerAd = null;
    _bannerSize = null;
  }

  @override
  void didUpdateWidget(
    covariant AdaptiveBannerSlot oldWidget,
  ) {
    super.didUpdateWidget(oldWidget);

    if (oldWidget.adsEnabled &&
        !widget.adsEnabled) {
      _disposeBanner();

      if (mounted) {
        setState(() {});
      }
    }
  }

  @override
  void dispose() {
    _bannerAd?.dispose();
    super.dispose();
  }

  @override
  Widget build(BuildContext context) {
    final ad = _bannerAd;
    final size = _bannerSize;

    if (!widget.adsEnabled ||
        ad == null ||
        size == null) {
      return const SizedBox.shrink();
    }

    return SafeArea(
      top: false,
      child: SizedBox(
        width: double.infinity,
        height: size.height.toDouble(),
        child: Center(
          child: SizedBox(
            width: size.width.toDouble(),
            height: size.height.toDouble(),
            child: AdWidget(ad: ad),
          ),
        ),
      ),
    );
  }
}
```

# 7. UMP / CONSENSO

Il consenso deve essere verificato a ogni avvio.

Struttura:

```text
APP START
↓
requestConsentInfoUpdate
↓
loadAndShowConsentFormIfRequired
↓
canRequestAds?
↓
inizializzazione/advertising
```

La voce:

```text
Privacy / Scelte privacy
```

deve essere nuovamente accessibile quando UMP indica che il Privacy Options Entry Point è necessario.

Per Android UMP 4.0.0:
- requestConsentInfoUpdate() resta il punto di refresh per-launch;
- loadAndShowConsentFormIfRequired() gestisce il form quando necessario;
- canRequestAds() va letto DOPO il refresh del consent state;
- showPrivacyOptionsForm() è il percorso canonico per permettere all'utente di
  modificare/revocare la scelta quando l'entry point è richiesto.

CONFIGURAZIONE SERVER-SIDE OBBLIGATORIA QUANDO PERTINENTE:
- app selezionata in AdMob Privacy e messaggi;
- messaggio europeo pubblicato;
- targeting coerente (SEE/UK/Svizzera oppure Everywhere secondo prodotto/policy);
- lingua predefinita + lingue aggiuntive coerenti con le lingue dell'app;
- privacy policy URL reale e raggiungibile;
- scelta "Nega il consenso" configurata secondo la UX/policy scelta.

Il messaggio UMP può essere aggiornato server-side senza rilascio di una nuova
APK se il client UMP è già integrato e funzionante.

Mai considerare il consenso una procedura eseguita una sola volta per sempre.

# 8. KOTLIN / JETPACK COMPOSE — IMPLEMENTAZIONE CANONICA

Per i progetti Android nativi già esistenti.

```kotlin
@Composable
fun AdaptiveBanner(
    adUnitId: String,
    adsEnabled: Boolean,
    modifier: Modifier = Modifier
) {
    if (!adsEnabled) return

    val context = LocalContext.current
    val configuration = LocalConfiguration.current

    val widthDp = configuration.screenWidthDp

    val adSize = remember(widthDp) {
        AdSize.getLargeAnchoredAdaptiveBannerAdSize(
            context,
            widthDp
        )
    }

    val adView = remember(adUnitId, adSize) {
        AdView(context).apply {
            this.adUnitId = adUnitId
            setAdSize(adSize)

            adListener = object : AdListener() {
                override fun onAdLoaded() {
                    Log.d("AdMob", "Banner loaded")
                }

                override fun onAdImpression() {
                    Log.d("AdMob", "Banner impression")
                }

                override fun onAdClicked() {
                    Log.d("AdMob", "Banner clicked")
                }

                override fun onAdFailedToLoad(
                    error: LoadAdError
                ) {
                    Log.w(
                        "AdMob",
                        "Banner failed: $error"
                    )
                }
            }

            loadAd(
                AdRequest.Builder().build()
            )
        }
    }

    DisposableEffect(adView) {
        onDispose {
            adView.destroy()
        }
    }

    AndroidView(
        factory = { adView },
        modifier = modifier
            .fillMaxWidth()
            .height(adSize.height.dp)
    )
}
```

Test Banner Android ufficiale:

```kotlin
const val TEST_BANNER_ID =
    "ca-app-pub-3940256099942544/9214589741"
```

THREADING ANDROID:
- inizializzare Mobile Ads su background thread;
- creare/manipolare AdView sul main thread;
- caricare/mostrare interstitial e altri full-screen ad sul main UI thread;
- se l'inizializzazione avviene in Dispatchers.IO, fare switch esplicito a
  Dispatchers.Main.immediate prima di chiamare API full-screen/UI.

Pattern minimo:

```kotlin
CoroutineScope(Dispatchers.IO).launch {
    MobileAds.initialize(context) {}

    withContext(Dispatchers.Main.immediate) {
        InterstitialAd.load(
            context,
            adUnitId,
            AdRequest.Builder().build(),
            callback
        )
    }
}
```

Non usare un catch globale che, a seguito di una singola eccezione di placement,
imposti adsEnabled=false per tutta la sessione.

# 9. INTERSTITIAL

Non sono il formato di default.

Consentiti soltanto in pause naturali:

```text
azione
↓
elaborazione
↓
azione terminata
↓
eventuale interstitial
↓
destinazione successiva
```

Non usarli:

```text
apertura app
cambio tab
apertura impostazioni
Back
pressione di normali pulsanti
lettura di risultati
azioni frequenti
```

Applicare inoltre un frequency cap interno.

Esempio concettuale:

```dart
bool canShowInterstitial({
  required bool premium,
  required bool naturalBreak,
  required Duration sinceLastAd,
}) {
  if (premium) return false;
  if (!naturalBreak) return false;

  return sinceLastAd >=
      const Duration(minutes: 3);
}
```

Il valore temporale è una scelta UX del prodotto, non una regola AdMob universale.

Per Android:
- preload/load/show devono rispettare il main UI thread richiesto dalle API;
- un failure di preload/show deve invalidare SOLO lo stato dell'interstitial;
- se l'interstitial è incluso nella release, la certificazione production
  richiede almeno una visualizzazione fisica nel natural break previsto,
  senza cliccare l'annuncio.

# 13. TEST MODE

Regola assoluta App Factory:

```text
DEBUG = TEST TRAFFIC
QA = TEST TRAFFIC
AUTOMATED TEST = TEST TRAFFIC
MANUAL TEST = TEST TRAFFIC
```

Default:
- usare i sample Test Ad Unit ID ufficiali.

Eccezione controllata per Ad Inspector / mediation / verifica di un Ad Unit reale:
- è consentito usare il proprio Ad Unit ID SOLO su un dispositivo registrato
  esplicitamente come test device;
- il traffico deve restare test traffic;
- mai cliccare/live-testare annunci reali non marcati come test.

Diagnostic UMP:
- è consentito forzare una debug geography (es. EEA) soltanto nella lane

  configuration non intenzionale.

Solo una normale:

```text
PRODUCTION SIGNED RELEASE
```

può usare gli Ad Unit ID reali fuori dal test-device mode.

# 14. LAYOUT FAILURE SAFE

Se l'annuncio non viene caricato:

```text
NO FILL
NETWORK ERROR
CONSENT DENIED
SDK ERROR
```

l'app deve continuare a funzionare normalmente.

Non lasciare:

- grandi spazi bianchi;
- loader infiniti;
- placeholder pubblicitari;
- UI bloccata;
- navigazione spostata.

FAILURE ISOLATION:
- banner failure != interstitial failure;
- interstitial failure != global monetization failure;
- no-fill/network error devono restare placement-local;
- disabilitare globalmente gli ads solo per condizioni realmente globali
  (Premium/Remove Ads, consenso non idoneo, configurazione production invalida,
  policy/kill-switch esplicito).

# 16A. FLUTTER WEB / DESKTOP BOUNDARY

`google_mobile_ads` è un plugin Android/iOS. Il Web Preview standard dell'App
Factory NON deve tentare di inizializzarlo o caricare AdMob.

Pattern obbligatorio:

```text
monetization/
├── ad_slot.dart              -> API comune
├── ad_slot_mobile.dart       -> google_mobile_ads
└── ad_slot_stub.dart         -> Web/unsupported: SizedBox.shrink()
```

Il Web Preview deve continuare a verificare:
- layout;
- navigazione;
- Premium/No Ads state;
- spazio pubblicitario quando utile come mock visuale;

ma NON è prova funzionale AdMob.

Regola:

```text
WEB PREVIEW GREEN
!=
ADMOB VERIFIED
```

Non inserire publisher ID inventati nei template Golden.

# 16D. AGE / AUDIENCE TREATMENT

Ogni app deve dichiarare esplicitamente il proprio audience model prima di
configurare advertising.

Non ereditare automaticamente da un donor:
- child-directed treatment;
- under-age-of-consent treatment;
- max ad content rating;
- ATT/IDFA behavior.

Per UMP e Mobile Ads, i tag relativi all'età devono essere configurati secondo
la Product Bible e le dichiarazioni store dell'app.

Android GMA Legacy 25.3.0+ ha introdotto setAgeRestrictedTreatment() e ha
deprecato i precedenti tag child-directed / under-age-of-consent: non copiare
alla cieca chiamate legacy da donor più vecchi. Verificare l'API della versione
pinnata.
