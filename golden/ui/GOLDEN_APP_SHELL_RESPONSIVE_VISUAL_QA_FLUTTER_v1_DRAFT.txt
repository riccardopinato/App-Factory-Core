======================================================================
3. RESPONSIVE RULE
======================================================================

Non assumere una sola larghezza telefono.
Verificare:
- small phone;
- large phone;
- tablet quando target;
- landscape quando target;
- fold/large display se pertinente.

Usare constraints/layout semantics, non coordinate magiche.

======================================================================
4. SAFE AREA / INSETS / EDGE-TO-EDGE
======================================================================

Controlli interattivi e overlay devono rispettare:
- status bar;
- navigation bar;
- gesture area;
- display cutout;
- keyboard/IME;
- bottom sheets;
- ad slots.

I pulsanti flottanti non devono uscire dallo schermo o sovrapporsi.

======================================================================
5. FONT SCALE / ACCESSIBILITY
======================================================================

Testare almeno normal + large font scale.
Evitare:
- fixed-height text containers;
- truncated CTA senza fallback;
- touch target piccoli;
- icon-only controls senza semantics/tooltip quando necessario.

======================================================================
6. UI STATES
======================================================================

Ogni screen data-driven deve definire:
- initial/loading;
- content;
- empty;
- recoverable error;
- blocking error quando reale;
- offline/degraded se pertinente.

No spinner infinito.

======================================================================
7. OVERLAY ZONES
======================================================================

Definire zone per:
- map controls;
- FAB;
- bottom nav;
- snackbars;
- banners ads;
- system insets.

Overlay multipli devono avere collision policy.
