PORT CONTRACT
SearchDocument(id, sourceRevision, type, text, tags, visibility, locale).
LexicalRetriever.query(query, filters, maxResults) -> scored candidate IDs.
EmbeddingEngine(id, dimensions).embed(text) -> finite fixed-size vector.
SemanticIndex.upsert/remove/rebuild; search(queryVector); stats().
HybridSearch.search -> ordered hits with excerpt, score and matching reasons.
RetrievalQuality.evaluate(labeledQueries,k) -> Recall@K and MRR.

INVARIANTS
- Auth/visibility filters apply BEFORE returning cached semantic or lexical hits.
- Delete, content edit and source revision invalidate the derived index.
- Embedding engine id or dimension mismatch requires rebuild, never stale decode.
- Lexical path works independently when embedding engine is unavailable.
- Stable input ordering/ties, duplicate IDs fused once, bounded query length.
- Explain lexical/semantic contributions; deterministic ranking with finite scores.
- LocalHashEmbeddingEngine uses 192-dimensional deterministic FEATURE HASHING;
  this is NOT a trained neural LLM and no external model download is implied.
- No hidden network calls, persisted prompt text or out-of-scope user content.
- GOLDEN_INCREMENTAL_PERSISTENT_INDEXING owns revision/invalidation policy.

CONSUMER TEST MATRIX
Exact keyword; semantic-only synonym; multilingual alias; no hits; filter isolation;
deleted item absent; engine/dimension mismatch; stale revision; 0/NaN vector;
stable ties under document shuffle; duplicate ID; lexical-only fallback;
curated Recall@K/MRR corpus with published fixture; 5000 documents CI benchmark.
Notes curated test has Recall@K=1 and MRR >=0.66 for ITS OWN fixture only.
Do not generalize to other data sets.

EXTRACTION
Build framework-neutral retrieval interface first. Keep persistent index and
semantic engine optional. Consumer must validate data isolation, real corpus
quality and memory/performance independently.
