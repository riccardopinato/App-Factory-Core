PORT CONTRACT
GeoItem(stableId, lat, lon, timestamp?, type?, metadata?).
ClusterPolicy = radiusMeters(radius, chainingRule) OR gridZoom(cellByZoom).
cluster(GeoItems, policy, zoom?, viewport?) -> ordered clusters with stable
member IDs, centroid, count, algorithm identity.

INVARIANTS
- Reject invalid lat/lon, NaN and missing coordinates (never map missing to 0,0).
- Radius in meters uses geodesic model; do not compare raw degrees to meters.
- Grid scaling must respond deterministically to zoom; no implicit map state.
- Radius transitive expansion is distinct from pairwise/complete-link clustering;
  choose and document policy, because chained clusters can span >radius.
- Anti-meridian and high-latitude boundary cases must not split near neighbors.
- Stable member IDs, canonical sorted set, deterministic cluster ID and order.
- Bound worst-case complexity (grid/buckets for large n).
- Clustering is derived; must not overwrite original user POI/visit IDs.

CONSUMER TEST MATRIX
Same location, threshold +/- epsilon, shuffle identical output, duplicate IDs,
two zoom levels, anti-meridian 179.9/-179.9, high latitude, invalid coords,
stable cluster hash, 10k POI broad CI regression, map FPS physical gate.

EXTRACTION
Keep CamperBoss grid mode and Wonderlog geographic radius mode as separately
selectable strategies under one small interface. Do not choose algorithm
implicitly by donor name, and do not silently claim equal clustering semantics.
