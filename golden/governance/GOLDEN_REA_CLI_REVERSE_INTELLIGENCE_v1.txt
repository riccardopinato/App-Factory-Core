0. GOLDEN SCOPE AND STATUS

This is a SCOPED CERTIFIED, on-demand, read-only RESEARCH PROCESS for handling
authorized local PE/Windows executable files through the REA CLI and the
existing AppLab research adapter. It is not a code library embedded in the
consumer app, not an always-on service, not an MCP integration, and not a
CERTIFIED GOLDEN or a universally certified reversing engine.

The scope verified so far is:
- pinned REA CLI version/runtime admission and local static introspection;
- bounded PE import and PE certificate observation via the AppLab adapter;
- static NSIS extraction of a source-authenticated PUBLIC Deskland installer
  using a separate archive tool, SHA-256 match for 43 published payload files;
- direct REA managed-assembly metadata observation on extracted Deskland.exe;
- traceable CLI output, checksums, evidence and no-execution boundaries.

These are SEPARATE operations; REA CLI bridge currently accepts only
inspect-pe-imports and inspect-pe-certificates. The direct managed inspection
and archive extraction were demonstrated inside a dedicated GitHub research
workflow, not generalized into the adapter. Do not imply one command does all.

The status does NOT certify:
- Windows runtime, installed registry state, or actual functional behavior;
- arbitrary EXE/PE/NSIS formats, malware safety, digital signature validity,
  device compatibility, extraction of proprietary source, or decompilation;
- recovery of a historical user installer uploaded in another conversation;
- every REA provider/engine, dynamic debugging, browser or APK analysis;
- clean-room Android port parity, APK hardware QA, store release;
- automatic donor/E3/E5 or Golden promotion for inspected software.

1. WHEN TO USE

Use only when the target software is owned by the user, officially available
for lawful research, or the investigation is otherwise authorized; a specific
question cannot be answered reliably from the accessible source; the analysis
is likely to add measurable insight; and a bounded, isolated static workflow
is proportionate. For normal Flutter/Kotlin app work when source/test/CI are
available, prefer source inspection, AppLab existing verification and
certified internal donor over reverse engineering.

Examples of acceptable on-demand usage:
- distinguish outer Windows installer from embedded executable architecture;
- enumerate PE imports/cert tables and identify missing coverage;
- compare official manifest and extracted payload hashes;
- map source-observed Windows functionality to independently implementable
  Android designs, without copying incompatible code/assets.

No automatic scan of all App Factory repositories or background service.

3. EXECUTION RECIPE (READ-ONLY, ON-DEMAND)

A. Resolve App Factory CURRENT, relevant Golden, product repository scope,
   ownership and license. Prefer existing source and certified donors first.
B. Locate the exact, authorized binary and capture the expected SHA-256 and
   length. Do not substitute a public build for a privately shared installer
   with a similar product name; label each binary independently.
C. Provide a controlled environment. Install a tested, explicitly versioned
   REA CLI independently of the app repository:
   npm install --prefix /abs/rea-tools --no-save --omit=optional --no-audit --no-fund rea-agents@6.9.0
   Node must report a supported version; verify REA --version --json.
   The npm package version is pinned, but this example is NOT a complete
   immutable transitive dependency lock. For production/high-trust runs,
   review/install with package-lock integrity and supply-chain controls.
D. Use the existing AppLab CLI adapter (not shell/MCP), for a confirmed PE:
   python scripts/rea_cli_bridge.py --rea-bin /abs/rea-tools/node_modules/.bin/rea
     --artifact /abs/sample.exe --output-dir /abs/private-output
     --repository OWNER/REPO --source-sha FULL_40_CHAR_SOURCE_SHA
     --operation imports --operation certificates
   Windows: provide full path to node.exe as --rea-bin, with absolute
   --rea-entry to the rea-agents/scripts/rea.mjs file; never invoke .cmd
   wrappers through a shell. Exact installed paths are environment-specific.
E. Adapter gates: pinned rea-agents 6.9.0 and compatible Node runtime;
   absolute regular local file; confirmed PE header; SHA-256 before/after;
   budget default 64 MiB, max 512 MiB; timeout default 45 s, max 180 s;
   bounded JSON and stdout; immutable evidence file collision checking.
   No execution of the input PE. Do not treat "0 PE imports" as "no native
   APIs": .NET may use P/Invoke or other native/dynamic mechanisms.
F. If approved and necessary, run additional *separate* static REA commands
   (for example inspect-managed-artifact) on isolated extracted files, or
   extract supported archives using third-party static tools; scope, version,
   license, budget, results and test each command independently. The
   restricted bridge does not cover these operations. No unzip path traversal.
G. Save JSON receipts, external evidence with hashes, commit SHA, workflow
   URL, analyzed filename/version, timestamps, command, coverage/limitations.
   Summarize what was directly observed and what remains unverified.
   External output is UNVALIDATED_EXTERNAL_OUTPUT until specific fields
   are reviewed. Do not promote into AppLab trusted runtime evidence.
H. Compare with source-only baseline: list findings genuinely unavailable
   from the sources and explicitly decide ADOPT / REFERENCE / DEFER / REJECT.
   License-clearance and independently authored Android implementation
   remain separate from the reverse-engineering discovery step.
I. Re-run dedicated consumer tests, exact-head CI, physical/provider/store
   gates *only where relevant*; never mark reverse-engineered code
   certified from documentation or static evidence alone.

5. SAFETY, LICENSE, SECURITY AND PRIVACY

- Inspect only authorized, lawfully acquired targets. No bypass of product
  controls, private account extraction or interception of third-party data.
- Run on disposable/isolated machine when possible. Do not execute untrusted
  files as part of static inspection, run hidden services, open ports, or
  grant unnecessary privileges.
- Do not upload user-provided private binaries, logs, secrets, decompiled
  contents or identifiers into public Actions or pull requests.
- REA is MIT licensed. Target and third-party engines keep THEIR OWN rights:
  the original Deskland is GPL-3.0. A permissive REA license does not grant
  permission to copy target software code, artwork or trademarks.
- Prefer patterns independently rewritten according to consumer license and
  product policy; record attributions where required.
- Trust hierarchy: binary hash != software safety; static import/certificate
  report != actual runtime/API call; CI PASS != hardware or Play readiness;
  valid PE metadata != provenance or Authenticode signature verification.
- Keep adapter outputs research-only; AppLab QA/certification Golden remains
  the canonical trusted runtime verifier, not this Golden.
